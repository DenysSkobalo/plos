\section{System Architecture Overview}

The PLOS backend is engineered following the Clean/Hexagonal Architecture pattern, enforcing a strict separation of concerns across software layers. The entire system is compiled into a single, static CGO-free binary targeting \textbf{Go 1.25.0}.

\section{System Level \& Storage Subsystem Mechanics}

\subsection{CGO-Free SQLite Driver \& Database Connection Pool}

The system utilizes \texttt{modernc.org/sqlite}, a pure Go SQLite implementation created via C-to-Go transpilation. This eliminates runtime dependencies on CGO, enabling true cross-platform \texttt{CGO\_ENABLED=0} static compilation and removing context-switching overhead between the Go goroutine stack and the C execution stack.

The connection pool is intentionally restricted to prevent file-level lock contention:
\begin{equation}
\text{MaxOpenConns} = 1, \quad \text{MaxIdleConns} = 1, \quad \text{ConnMaxIdleTime} = 5\text{ minutes}
\end{equation}

Restricting SQLite writes to a single open connection serializes write operations at the application level, completely preventing \texttt{SQLITE\_BUSY} lock errors.

\subsection{SQLite Hardware Sympathy Configuration (Pragmas)}

The database is initialized using optimal SQLite Pragmas tuned for SSD/NVMe storage mechanics:
\begin{itemize}
    \item \texttt{journal\_mode(WAL)}: Enables Write-Ahead Logging. Readers do not block writers, and writers do not block readers, achieving concurrent execution throughput.
    \item \texttt{synchronous(NORMAL)}: Eliminates unnecessary \texttt{fsync()} system calls on every transaction commit, syncing only during WAL checkpointing.
    \item \texttt{busy\_timeout(5000)}: Enforces an internal 5000ms retry backoff loop when lock contention occurs.
    \item \texttt{foreign\_keys(1)}: Enforces relational foreign key constraints on every mutation.
\end{itemize}

\section{Cashflow Engine Mechanics}

The \texttt{CashflowEngine} is a pure, deterministic domain engine free from I/O dependencies or system calls.

\subsection{Mathematical Model of the Two-Phase Cascade Algorithm}

Let the exchange rate for EUR/UAH be $R_{\text{buy}}$. Foreign currency amounts are normalized to the base currency (EUR):
\begin{equation}
\text{Amount}_{\text{EUR}} = 
\begin{cases} 
\text{Amount}, & \text{if Currency} = \text{EUR} \\ 
\frac{\text{Amount}}{R_{\text{buy}}}, & \text{if Currency} = \text{UAH} 
\end{cases}
\end{equation}

The total available liquidity for the monthly period is calculated as:
\begin{equation}
C_{\text{avail}} = \sum \text{Income}_{\text{EUR}} - \sum \text{Expense}_{\text{EUR}}
\end{equation}

\subsubsection{Phase A: Mandatory Minimum Payments}
For each active debt $d_i \in D$, the mandatory minimum payment is applied regardless of priority:
\begin{equation}
P_{\text{min}, i} = \min\left(\text{MinPayment}_{\text{EUR}}(d_i), \text{Remaining}_{\text{EUR}}(d_i), C_{\text{avail}}\right)
\end{equation}
\begin{equation}
\text{Remaining}_{\text{EUR}}(d_i) \leftarrow \text{Remaining}_{\text{EUR}}(d_i) - P_{\text{min}, i}
\end{equation}
\begin{equation}
C_{\text{avail}} \leftarrow C_{\text{avail}} - P_{\text{min}, i}
\end{equation}

\subsubsection{Phase B: Cascade Priority Surplus Distribution}
Iterating through active debts sorted in strict priority order ($P_1 \to P_n$), remaining available liquidity $C_{\text{avail}}$ is cascaded:
\begin{equation}
P_{\text{extra}, k} = \min\left(C_{\text{avail}}, \text{Remaining}_{\text{EUR}}(d_k)\right)
\end{equation}
\begin{equation}
\text{Remaining}_{\text{EUR}}(d_k) \leftarrow \text{Remaining}_{\text{EUR}}(d_k) - P_{\text{extra}, k}
\end{equation}
\begin{equation}
C_{\text{avail}} \leftarrow C_{\text{avail}} - P_{\text{extra}, k}
\end{equation}

To avoid floating-point representation anomalies ($\epsilon$-precision errors):
\begin{equation}
\forall d_i \in D, \quad \text{if } \text{Remaining}_{\text{EUR}}(d_i) \le 0.01 \implies \text{Remaining}(d_i) = 0, \quad \text{Status}(d_i) = \text{PAID}
\end{equation}
